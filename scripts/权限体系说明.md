# 权限体系实施说明

## ✅ 已完成的功能

### 1. 角色定义
- **admin**: 管理员 - 拥有所有权限
- **user**: 普通用户 - 仅拥有内容创作和个人管理权限

### 2. 权限中间件

#### 2.1 RoleGuard 中间件
位置：`internal/middleware/rbac.go`

```go
// 校验用户是否具有指定的角色
middleware.RoleGuard("admin")  // 仅允许管理员
middleware.RoleGuard("admin", "editor")  // 允许管理员或编辑
```

#### 2.2 IsAdmin 快捷方法
```go
middleware.IsAdmin()  // 等价于 RoleGuard("admin")
```

### 3. 路由权限控制

#### 3.1 公开路由（无需登录）
- GET `/api/articles` - 获取文章列表
- GET `/api/articles/:id` - 获取文章详情
- GET `/api/categories` - 获取分类列表
- GET `/api/categories/:id` - 获取分类详情
- GET `/api/tags` - 获取标签列表
- GET `/api/tags/:id` - 获取标签详情
- GET `/api/comments` - 获取评论列表
- GET `/api/comments/:id` - 获取评论详情
- POST `/api/articles/:id/like` - 点赞文章
- DELETE `/api/articles/:id/like` - 取消点赞
- GET `/api/users/:id` - 获取用户公开资料

#### 3.2 认证路由（需要登录）
- GET `/api/auth/me` - 获取当前用户信息
- POST `/api/auth/logout` - 登出
- PUT `/api/users/profile` - 更新个人资料
- PUT `/api/users/password` - 修改密码
- POST `/api/articles` - 创建文章
- PUT `/api/articles/:id` - 更新自己的文章
- DELETE `/api/articles/:id` - 删除自己的文章
- POST `/api/comments` - 创建评论
- PUT `/api/comments/:id` - 更新自己的评论
- DELETE `/api/comments/:id` - 删除自己的评论

#### 3.3 管理员专属路由
- POST `/api/categories` - 创建分类
- PUT `/api/categories/:id` - 更新分类
- DELETE `/api/categories/:id` - 删除分类
- POST `/api/tags` - 创建标签
- PUT `/api/tags/:id` - 更新标签
- DELETE `/api/tags/:id` - 删除标签

### 4. 资源所有权校验

#### 4.1 文章管理
- 普通用户只能操作自己的文章
- 管理员可以操作任意文章
- Service 层自动校验权限：`UpdateArticle(id, req, userID, isAdmin)`

#### 4.2 评论管理
- 普通用户只能操作自己的评论
- 管理员可以操作任意评论
- Service 层自动校验权限：`UpdateComment(id, req, userID, isAdmin)`

## 🚀 使用指南

### 第一步：创建管理员账号

运行初始化脚本：

```bash
go run scripts/init_admin.go <username> <email> <password>
```

示例：

```bash
go run scripts/init_admin.go admin admin@example.com Admin@123
```

### 第二步：测试权限体系

#### 1. 管理员登录
```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin",
    "password": "Admin@123"
  }'
```

保存返回的 token。

#### 2. 测试管理员权限（创建分类）
```bash
curl -X POST http://localhost:8080/api/categories \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "技术文章",
    "description": "技术类文章分类"
  }'
```

#### 3. 创建普通用户并测试
```bash
# 注册普通用户
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "email": "test@example.com",
    "password": "Test@123"
  }'

# 普通用户登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "password": "Test@123"
  }'
```

#### 4. 测试权限拒绝（普通用户尝试创建分类）
```bash
curl -X POST http://localhost:8080/api/categories \
  -H "Authorization: Bearer <user_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "测试分类",
    "description": "应该被拒绝"
  }'
```

预期返回：
```json
{
  "code": -1,
  "message": "权限不足",
  "data": null
}
```

## 🔧 扩展指南

### 添加新的管理员路由

在 `internal/router/router.go` 的 `adminOnly` 组中添加：

```go
adminOnly.POST("/your-resource", (&api.YourHandler{Handler: handler}).CreateResource)
```

### 添加新的资源所有权校验

在对应的 Service 方法中添加 `isAdmin` 参数：

```go
func (s *YourService) UpdateResource(id uint, req YourRequest, userID uint, isAdmin bool) error {
    resource, err := s.repo.GetByID(id)
    if err != nil {
        return err
    }
    
    // 验证权限：管理员或所有者
    if !isAdmin && resource.OwnerID != userID {
        return errors.New("permission denied")
    }
    
    // ... 更新逻辑
}
```

在 Handler 中判断角色：

```go
func (h *YourHandler) UpdateResource(c *gin.Context) {
    id := getID(c)
    userID := middleware.GetUserIDFromContext(c)
    
    // 判断是否为管理员
    role, _ := c.Get("role")
    isAdmin := role == "admin"
    
    // 调用 Service
    err := h.Service.UpdateResource(id, req, userID, isAdmin)
    // ...
}
```

所有权限拒绝事件都会被记录到日志中：

```
[WARN] Permission denied: user=testuser, role=user, path=/api/categories, required_roles=[admin]
[WARN] Delete article failed: permission denied, articleID=1, authorID=2, requestUserID=3, isAdmin=false
```

## 🔐 安全特性

1. **JWT Token 包含角色信息**：登录时角色会被编码到 Token 中
2. **Session 验证**：每次请求都会验证数据库中的最新角色
3. **资源所有权保护**：即使有登录态，也只能操作自己的资源（除非是管理员）
4. **详细的审计日志**：所有权限拒绝事件都会被记录

## ⚠️ 注意事项

1. 管理员账号只能通过脚本创建，不能通过注册接口创建
2. 修改用户角色后，需要重新登录才能生效（因为角色编码在 Token 中）
3. 所有权限校验都在 Service 层和路由层双重保护
4. 默认注册的用户角色都是 `user`
